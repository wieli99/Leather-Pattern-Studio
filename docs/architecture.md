# Browser-first architecture

The Vue 3 + TypeScript interface presents panels and commands; a framework-independent TypeScript controller owns tool state, camera, selection, snapping and temporary previews. Canvas 2D renders via an animation-frame scheduler, independently of Vue rendering. Backing resolution changes only with viewport size/device pixel density.

A Rust core compiled with wasm-pack runs in a dedicated Web Worker and owns typed, validated documents and transaction history. Contracts are generated with ts-rs. Requests carry revision numbers; preview responses are discarded when obsolete. Pointer previews are coalesced. UI previews never modify authoritative history. One commit represents one gesture or accepted field edit; history retains the last 200 commits. Spatial hit testing and snap candidates are derived from the display snapshot in TypeScript to keep pointer interaction immediate.

Version-5 documents store IDs, names, primitive kinds, local defining points, corner radius, rotation and an optional affine transform. Shapes use double-precision millimetres. Circles use centre plus radius endpoint; rectangles/ellipses use opposite corners; lines and polylines use vertices. Rotation is around the primitive's centre. Uniform group scaling preserves circles. Imported version-1 stitch parameters remain inactive metadata. Unsupported or invalid projects never replace the current document.

Browser file handles provide native saves where available, with explicitly reported downloads elsewhere. Debounced IndexedDB snapshots provide recovery after all committed changes, including undo/redo. A production-only service worker precaches the application, worker and Wasm. Each build gets a separate cache; updates wait for explicit activation so active sessions are not replaced.

All builds, dependency installation, development and tests run through Podman on Bluefin. The immutable host is not modified. Browser delivery supports Linux, Windows and macOS without native packaging; automated browser-engine checks do not replace physical OS/device input validation.

Vue single-file components live in `src/vue/`. The controller stays outside Vue deep reactivity; scoped selector subscriptions invalidate only the UI, hover, or cursor views that changed. Reka UI provides unstyled menus, Settings popovers and the Help dialog. Build-time `vue-tsc` checks templates as well as TypeScript.

Circular arcs retain their center, defining radius point, rotation and signed sweep. Earlier project versions migrate on load; display precision never rounds stored coordinates.

Transform sessions are controller-owned previews. Selection does not activate a transform. Dedicated gizmos and numeric controls share a session; Apply commits once through Rust and cancellation invalidates pending worker responses. Version-5 shapes optionally store an affine matrix in Canvas convention (`x′ = a*x + c*y + e`, `y′ = b*x + d*y + f`), applied after primitive rotation about its local center. Parametric curve centers and basis vectors are transformed exactly for rendering, extrema, snapping, picking, and marquee selection. Primitives and inactive legacy metadata remain intact.

## Stitch runs and transfer placement

Format 21 stores repeatable transfer placement instances with a rigid angle and offset in piece-relative millimetres. The piece frame removes layout translation/rotation while retaining physical shape geometry. Each assignment references one source line and receiving piece; multiple placements for the same pair are supported. Format-20 point-pair registration is migration-only, with invalid legacy data retained behind a warning.

Detached transfers become native stitch-only guide shapes attached through `stitchParentId`, with fixed-count runs and start offsets preserving the included hole intervals. They use the existing Select-mode geometry editor. Receiving-only copies retain independent editable guides; source-plus-receiver copies remap their relationships. Printing resolves attached guide holes into the receiving piece and avoids duplicating them when both pieces and guides are imported. Legacy fixed-hole data gets a guide while retaining its custom initial placement until position-affecting edits.

Selection and placement previews remain transient controller state. Ctrl-click selects holes, Alt-click selects object stitching, and placement clicks commit the current stitch session and all successful assignments atomically. Rust owns saved contracts, validation and history. Canvas, picking, safety checks, clipboard and export share the same resolved hole geometry.

Stitch presets live in the validated browser library `leather-stitch-presets`, with versioned JSON export/import and explicit merge-or-replace review. Legacy embedded project presets remain compatibility data and can be imported explicitly. Library edits are immediate and independent of document history.

Stitch mode now has an explicit, transient active operation (`stitchTool`). Its bottom toolbar shares transform-toolbar styling; settings and Apply/Cancel remain contextual. Toolbar eligibility and disabled reasons are owned by the controller. Link, Unlink, Merge, Split and Delete previews rebuild from the committed stitch baseline and an input selection, preventing accumulated mutations when the selection or split method changes. Switching or cancelling restores the baseline; Apply commits one history entry and returns to neutral Stitch selection. Native path editing is a navigation action into Select mode. Operation state is not serialized.

The Stitch line tool creates independent sections on free source-edge intervals and Shift-created continuations after a selected section. Continuations accept Auto count; overlap checks reject intersecting spans and duplicate holes. Geometry reconciliation maps logical rectangle edges through polygon conversion rather than requiring their old world endpoints to survive. Multi-line merge processes selected groups in order and refuses disconnected intermediate chains atomically. DEL removes source stitching immediately in one history entry.

Transfer hover keeps a last-pose preview snapshot shared by canvas and options, with stable temporary relationship IDs and a shared receiving-geometry cache for the immutable render document. Pointer bursts are coalesced by animation frame and flushed before placement confirmation. Material safety checks retain exact segment/intersection tests while using spatial cells and Y buckets to reduce candidates. Fixed-hole paths use direct cumulative distances rather than projecting every hole against the entire path.

Transfer placement has transient hover and placed phases. Left-click freezes or repositions the preview without committing document state; Apply, right-click or Enter confirms a placed preview as one history entry. Queued hover input cannot move a placed preview. Rotation retains its placed center, while zoom and pan only change the viewport. Continue run requires a fixed-count predecessor with room for another hole; its child may use Auto count.

Rigid Model, print and transfer movement share compatible axis snapping; an anchor hint does not exclude other moving anchors. Vertex/quadrant targets outrank midpoint and center coincidences. Print-page centering cannot replace an object snap. Transfer placements carry an optional positive `number`, shared by all their source/receiver relationships; parsing fills missing values, copying allocates new placement IDs/numbers, and normal deletion does not renumber surviving placements.
